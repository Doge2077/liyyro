# RSI 的适用与评估

## 1. 一个看似成功的进化

一个团队给 Agent 加了自进化机制，跑了三个月。评测集分数从 61% 升到 74%，团队很满意。

接入真实用户后，投诉没有减少。逐条看失败案例，发现三类问题：新加的规则在长任务里被压缩掉了，模型后期不再遵守；某些任务分数涨了，但涨的原因是模型更愿意给「看起来完整」的答案，问题本身未必解决；还有一类任务，规则之间互相冲突，模型在不同轮次给出不同做法。

三个问题的共同点：**分数在涨，能力未必在涨。** 这正是 RSI 评估要解决的核心难题。

## 2. 两种能力必须分开测

RSI 里有两件事容易被混成一个分数。

**更新能力**：从轨迹中产生有价值的持久修改。它衡量的是「更新器好不好」。

**受益能力**：任务 Agent 在后续运行中找到、激活并正确使用这些修改。它衡量的是「产物能不能被用上」。

为什么必须分开：一个 Skill 可能写得完全正确，但任务模型没有在合适场景加载它，或加载后无法长期遵循。这两种情况都会让最终成绩看起来「没有进化」，但原因完全不同——前者要改检索或目录描述，后者要改 Skill 的写法或任务模型的选择。

用端到端分数反推更新器好坏，会把三种失败混成一种。

有一条实证支持这个区分：在模型替换实验里，这两种能力与基础模型能力的关系并不相同。基础模型强，受益能力明显上升；更新能力不随基础模型强度线性上升。

## 3. 四层指标

四层指标逐层收紧。

### 提案有效率

答案的问题：更新器是否提出了有价值的修改。

证据：提案在独立验证中的接受率与增益。

假阳性：提案对生成它的那批轨迹有效，对别的轨迹无效。这类假阳性在样本少时特别常见——三条轨迹支持一条规则，看起来证据充分，实际上只是这三条恰好有共性。

检验方法：把提案放到生成它时没见过的轨迹上评估。如果增益消失，说明提案过拟合。

### 产物激活率

答案的问题：任务 Agent 是否在正确场景加载了新 Skill、记忆或工具。

证据：检索、路由与工具调用的轨迹。

假阳性：分数涨了但不是因为这个产物——可能是同时上线的另一个改动起了作用。

检验方法：单独回放「有产物」与「无产物」两组，其余条件相同。

### 遵循成功率

答案的问题：激活后是否按新规则或流程执行。

证据：动作序列与过程验证器。

假阳性：短任务看不出偏离。一条「失败后先查环境」的规则，在任务只有两步时看不出差别；在二十步的长任务里，模型可能在中途就忘了。

检验方法：构造长任务用例，检查规则在整个任务周期内的遵守情况，特别是压缩发生后的遵守情况。

### 保留集增益

答案的问题：整体是否改善了未参与进化的任务，是否有泛化。

证据：保留集成功率、质量与成本。

假阳性：保留集与训练集重叠。这是最常见也最致命的假阳性——如果保留集里的任务在提炼时被看过，它就不再是保留集。

检验方法：保留集在冻结前只用于评测，不参与任何调优决策；定期检查保留集与训练集的文本重叠度。

## 4. 回放作为评估环境

外层搜索（改工作流、改框架代码、改优化器）的评估成本很高：每个候选都要重跑 Agent 与评估器。

一个缓解办法是把已完成的探索保存成可回放的树。根节点是初始状态，每个子节点保存从某个历史状态继续尝试后的工作区快照、候选产物、评估诊断与分数。

候选策略与在线时用同一套接口，逐步选择要展开的叶节点或从根节点开新分支。回放器只揭示已记录的结果，不重跑底层 Agent 与评估器。

这条机制成立需要两个条件：

第一，在线与离线使用相同的决策接口。否则离线学到的策略无法迁移到在线。

第二，只向策略逐步揭示当前已展开的子树。否则策略会偷看在线时不可能知道的未来结果，学到的东西在真实环境中无效。

它能做什么：比较不同的分支、顺序、并行批次与停止时机。

它不能做什么：证明在旧树上得分更高的策略能迁移到新任务。它只是历史重组，不是世界模型。

这个限制值得强调，因为「在回放上分数很高」很容易被误读成「策略更好」。回放的优势是便宜，代价是它只覆盖历史里走过的路径。

## 5. 三类失效

### 实现漂移

症状：原方案一旦变难，Agent 逐渐退回训练数据里更熟悉、但已经偏离原假设的做法。分数可能还涨了，因为它换成了更容易拿分的做法。

成因：目标函数没有覆盖「必须按这个方案做」，只覆盖了「结果要对」。

识别方法：对比早期与后期的动作序列，看是否出现系统性的方法替换。

### 认识论过度乐观

症状：信号还只是噪声，系统已开始解释结果、打补丁、宣布发现。失败与阴性结果被忽略。

成因：更新循环只看到幸存案例——失败的尝试没有被记录，所以归纳时只看到「成功的那些有什么共性」。

识别方法：检查失败案例是否被记录与聚合。如果日志里只有成功案例，这一条几乎必然发生。

### 隐性判断力不足

症状：Agent 能跑实验，但不知道哪个基线真正重要、哪个异常值得追踪、何时应该放弃假设。

成因：这类判断难以写成规则，也难以用分数衡量。

识别方法：人工审阅若干条完整的探索轨迹，看它是否在明显该放弃时继续投入。

## 6. 安全约束

四类措施，各自对应一类风险。

**结论与证据分离。** 对引用、数字、方法与结论分别记录证据来源，最终输出只是证据图的一种呈现。这提高的是可追溯性，不保证结论有价值。

**保留负面结果。** 失败实验、被拒提案、停止原因都写入日志。否则进化模块只看到幸存方案，会反复探索已经证伪的路径。

**维护搜索多样性。** 不只保留当前得分最高的一条链。备选池需要保留若干暂时低分但类型不同的分支，避免所有方案收敛成同一个容易拿分的模板。

**让人在更高层介入。** 人的作用不止是在危险动作前点「批准」，还包括定义问题、审查评价标准、解释反常结果、决定何时停止。

第四条常被简化成「人工审批」，但审批只覆盖单次动作。真正的判断发生在更上层：这个方向值不值得做、这个指标定得对不对、这个异常是噪声还是信号。

## 7. 什么时候不该做自进化

三条判据，任何一条成立就应当放弃自动进化。

**第一，评价信号来得很慢或不唯一。** 开放式研究、战略规划、复杂产品设计属于这一类。此时 Agent 可能把流程执行得很完整，却只是稳定地产出「像成果的东西」。自动进化会把这种稳定当成进步。

**第二，没有可回滚的发布机制。** 如果一次错误的更新无法撤销，自动化的收益不值得承担风险。回滚能力的缺失通常意味着整个发布流程需要先建。

**第三，失败案例无法被稳定记录。** 如果系统只记得成功，归纳必然有偏。这一条对应的正是「认识论过度乐观」的成因。

三条之外还有一条弱判据：**如果改动的实际执行者是人**（例如每次更新都要人工改一段提示词），那么「自进化」只是把人的工作换了个说法。此时更值得优化的是人的工作效率，建一套自动管线的收益有限。

## 8. 一条实用的评估顺序

如果要给一套 RSI 系统做体检，建议按这个顺序。

第一步，查日志完整性：失败案例有没有被记录。这一项不过，后面都不用做。

第二步，查保留集：它是否真的独立于调优过程。做法是看它有多久没被用于决策。

第三步，分开测两种能力：用一个固定的任务模型测更新能力，用一个固定的更新器测受益能力。

第四步，查激活率与遵循率：产物有没有被加载、加载后有没有被遵守。这两项能定位到「写得不好」还是「用不上」。

第五步，查长任务：规则在压缩后是否还遵守。这一项最容易被忽略，也最容易在真实使用中暴露。

五步之中，前两步是前提，后三步是诊断。跳过前提直接看分数，会得到第 1 节那个后果——分数涨了，投诉没少。
